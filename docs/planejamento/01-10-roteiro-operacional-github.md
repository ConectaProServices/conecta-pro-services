# 01-10 - Roteiro Operacional de Configuração no GitHub

## Passo a passo

1. Acessar o repositório do projeto no GitHub.
2. Criar a Issue principal do épico com o título `[UC01] Solicitar Agendamento`.
3. Descrever objetivo, contexto, escopo e critérios de aceite da Issue principal.
4. Criar as Sub-Issues conforme os identificadores `SUB-01` até `SUB-06`.
5. Vincular cada Sub-Issue ao épico por meio de checklist ou referência direta no texto.
6. Inserir descrições, requisitos de origem e critérios de aceite de cada atividade.
7. Criar as labels propostas no repositório.
8. Aplicar as labels no épico e nas Sub-Issues conforme o contexto funcional.
9. Criar o GitHub Project em modo Kanban.
10. Configurar as colunas exatamente com: `Backlog`, `Ready`, `In Progress`, `In Review` e `Done`.
11. Adicionar as Issues e Sub-Issues ao Project.
12. Atribuir responsáveis definidos na matriz de responsabilidades.
13. Revisar a consistência do quadro e garantir que não haja tarefas sem rastreabilidade.
14. Confirmar que as dependências principais aparecem visíveis no board.

## Observações técnicas

- A Issue principal deve ficar como centro do fluxo de planejamento.
- O board deve priorizar a disciplina e a rastreabilidade da implementação futura.
- A criação das labels deve preceder a organização do board para reduzir retrabalho.
- As Issues de testes e exceções devem ficar devidamente sinalizadas para facilitar a revisão antes do início da execução.
